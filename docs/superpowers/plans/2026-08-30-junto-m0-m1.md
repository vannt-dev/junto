# M0 + M1 implementation record

- Original plan date: 2026-08-30
- Completed: 2026-09-05
- Authoritative design: `docs/superpowers/specs/2026-08-30-junto-design.md`

This document replaces the original step-by-step Vietnamese execution plan with an English implementation
record. The design document remains authoritative when details differ.

## Delivered tasks

### Task 1 - UserPromptSubmit approval spike

The implementation accepts both an exact `/junto:approve` prompt and the fixed
`JUNTO-APPROVE-SENTINEL-7f3a9c` embedded in the expanded command. Interactive acceptance in a locally installed
Claude Code plugin remains a manual verification step.

### Task 2 - Workspace scaffold

Created the pnpm TypeScript workspace, strict shared compiler settings, Vitest configuration, package projects,
LF normalization, and root project references. Commands use `corepack pnpm` and Node.js 20.19+ or 22.12+.

### Task 3 - Schema and version policy

Implemented Zod schemas for tasks, configuration, phases, gates, decisions, and verdicts. `SCHEMA_VERSION` is 1.
Future schema versions fail closed with an explicit upgrade error.

### Task 4 - Paths and persistence

Implemented `.junto` path helpers, upward project discovery, active-task storage, validated task/config reads,
atomic task writes, and locked read-modify-write updates. Project discovery only accepts a real `.junto` directory.

### Task 5 - Pure transition policy

Implemented `requiredPhases()` and pure `canEnter()` rules. The policy has no filesystem, clock, environment,
randomness, or mutation dependencies. Required gates must have readable, non-stale pass verdicts.

### Task 6 - Stale matching

Implemented the small glob matcher used by `staleIgnore`, including `**`, `*`, and `?` semantics with normalized
path separators.

### Task 7 - Gate execution

Implemented real argv-array process execution, timeout handling, executable resolution, pass/fail/skipped states,
full logs, bounded UTF-8-safe output tails, safe gate names, Windows device-name rejection, and POSIX executable checks.

### Task 8 - Task MCP tool

Implemented start, switch, and finish actions. IDs are normalized and path-safe. Creation fails closed on active or
archived collisions. Finish only archives a task in the done phase and never overwrites an existing archive.

### Task 9 - Verify MCP tool

Implemented gate selection, sequential execution, per-gate durable task updates, verdict linking, and real-failure
streak accounting. Skipped gates neither increment nor reset failure streaks.

### Task 10 - Advance MCP tool and server wiring

Implemented disk-backed `TransitionContext`, phase transitions through core policy, three MCP tool registrations,
and a dedicated stdio entry point. The server bundle is tested through a real MCP client handshake.

### Task 11 - State hook

Implemented compact state injection and user-only plan approval. Hook output uses `additionalContext`, matches exact
raw commands or the expansion sentinel, and records approval through a locked update.

### Task 12 - Guard hook

Implemented PreToolUse protection for active state, task state, lock/temp files, and verdicts. PostToolUse invalidates
existing verdicts after relevant edits while respecting `staleIgnore`.

### Task 13 - Session and handoff hooks

Implemented session restoration for brief, plan, and decisions. Handoff reads selected context rows and supports the
current `Agent` tool name plus the legacy `Task` alias.

### Task 14 - Self-contained plugin packaging

Added plugin/marketplace manifests, hooks and MCP configuration, four bundled hooks, and one bundled MCP server.
All configured paths are relative to `${CLAUDE_PLUGIN_ROOT}` and artifact tests reject external package imports.

### Task 15 - Slash commands

Added `/junto:start`, `/junto:plan`, `/junto:approve`, `/junto:verify`, and `/junto:finish`. Commands guide Claude
through configuration discovery, explicit approval, deterministic verification, and fail-closed archival.

### Task 16 - Boundary tests, CI, and README

Added end-to-end R1 boundary tests, Windows/Linux CI, artifact synchronization checks, documentation, and a real
stdio MCP test. The final local suite passed with the POSIX-only executable-bit case intentionally skipped on Windows.

## Durable implementation decisions

1. `server.ts` only constructs the MCP server; `main.ts` is the unconditional executable entry.
2. State and guard hooks use a short-lived lock around task read-modify-write operations.
3. Missing executables are detected before spawn rather than inferred from localized output text.
4. Gate evidence is persisted after every completed gate so a later error cannot erase earlier results.
5. Task size policy and phase ordering remain centralized in core transition functions.
6. Generated plugin artifacts are committed and must reproduce without a diff.
7. The plugin supports both `Agent` and the older `Task` tool name for handoff compatibility.

## Remaining manual acceptance

Installing the plugin changes Claude Code state outside this repository, so it is not part of automated CI. Manual
acceptance should verify a small-task lifecycle, stale evidence after an edit, guard denial for protected files, and
a standard task blocked from build until the user invokes `/junto:approve`.

## Deferred milestones

M2 and M3 will add API/CLI model backends, architect/adversary/pragmatist/reviewer roles, consult and panel tools,
token budgets, and panel/review phases for deep tasks. Those features remain intentionally out of M1.
